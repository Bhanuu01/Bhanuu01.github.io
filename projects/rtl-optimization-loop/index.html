RTL Optimization Loop

An AI-assisted workflow for synthesis, timing analysis, and iterative RTL patch review.

Verilator · Yosys · OpenSTA · Python · LLM-assisted tooling

This project started from a familiar frustration in digital-design work: the time cost of repeatedly running simulation, synthesis, and timing checks just to get back to the next debugging decision. Instead of treating those tools as disconnected steps, I wanted a tighter loop that could surface failures, summarize them, and support the next edit more quickly.

Problem

RTL development often involves a repetitive sequence: run simulation, inspect failures, resynthesize, check timing, adjust the code, and repeat. The cost is not only wall-clock time but also context-switching. When the loop is noisy, it is harder to focus on the actual hardware reasoning.

What I built

I built a workflow that runs Verilator, Yosys, and OpenSTA in sequence, collects the relevant outputs, and uses an LLM-guided patching step to propose the next edit candidates. The point was not to create push-button hardware design. It was to reduce the amount of repeated setup work around each iteration.

How the loop works

Each pass runs linting and simulation, then synthesis and timing analysis, and finally packages the most useful feedback into a form that is easier to review. That structure made the workflow useful even without a dramatic benchmark number, because it clarified where the next engineering decision should come from.

Why it matters

I included this project because it reflects another side of my interests: tooling and developer loops. The same instinct shows up in my backend and ML systems work too. I care about shortening the path between “something failed” and “here is the next change worth making.”

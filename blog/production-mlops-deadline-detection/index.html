MLOps

Lessons from turning a deadline extraction model into a production MLOps workflow

May 10, 2026 · 6 min read

The Datanauts project became useful to me when it stopped being just a model and started becoming a workflow. The modeling problem mattered, but the stronger engineering question was what happens when an output has to be reviewable, reproducible, and shaped for downstream use.

Why the system needed stages

Contract language is messy in ways that make naive extraction unreliable. A gating classifier was useful because it separated “is this clause even relevant?” from “which exact span should be extracted?” That boundary reduced noise and made the full pipeline easier to reason about.

What made it feel more real

MLflow tracking, artifact management, confidence thresholds, and review paths mattered as much as the model choice. Once a system is expected to support a real workflow, the surrounding structure determines whether the output is actually usable.

What I would add next

The main missing piece is stronger monitoring for drift. The offline metrics were good, but production confidence should not depend only on those metrics. A better version would make distribution change more visible over time.
